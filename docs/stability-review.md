# 长期运行稳定性审查与回归测试

审查基线：`99df337068abe666c1ff712f1bac9ff9a3092b77`。全仓库扫描覆盖 Go 入口、后台任务、定时器、共享状态、HTTP、子进程、日志、数据库和退出清理；人工深查集中于长期运行路径。不能把自动检查与重点审阅解释为已证明所有代码没有缺陷。

## 已修复的故障路径

### 根界面定时器重复排队

`RootModel.Update/wakeup` 原来会在已有待触发定时器时再次安排定时器，也会在任务结束时丢失待触发 spinner 的所有权。旧通知先到时，新通知的剩余有效期反而可能没有清理定时器。现在 spinner 与通知各自最多保留一个待触发命令，只有对应消息到达才清除 pending 标记，并按剩余期限重新调度。内部节拍不再转发到页面。

`TestRootStability*` 覆盖两万次消息更新、任务切换和通知延期。测试先于修复提交，旧代码上的三项失败可在 PR 的测试记录中核对。

### 磁盘日志故障影响内核

原来的 `io.MultiWriter(disk, buffer)` 把磁盘写入错误返回给 `os/exec` 的管道复制器；复制终止可能关闭子进程输出管道，并使持续写日志的内核收到 SIGPIPE。现在主内核 stdout/stderr 共用一个并发安全的容错日志接收器。磁盘故障不会停止读取子进程输出，内存日志继续保留，并在每次故障开始、恢复时记录提示。没有添加吞掉任意 panic 的全局 recover。

测试包含超过管道容量的真实子进程输出、旧 MultiWriter 对照、模拟磁盘失败/短写/恢复，以及通过 Manager 启动子进程后关闭日志文件的集成场景。

### 轮转失败与日志容量

轮转现在检查 rename 错误，不再把已关闭句柄当成可写文件；临时故障消除后，下次写入可以重试。显式 Close 后不会重新打开。单次超大 Write 也必须遵守单文件大小限制。

内存缓冲不再截断单条日志。除行数上限外，它按“容量 × 16 KiB”维护软总字节预算：超预算时轮转最旧的完整记录，不改写当前记录；若单条记录自身超过预算，会先完整保留，并在后续日志到达时按整条记录轮转。日志页按终端宽度自动换行，回看位置可落在同一条日志的续行上，因此长记录可以从头到尾查看。磁盘日志仍完整写入并沿用 5 MiB/文件、3 份备份的默认配置。

### 高频 API 轮询分配与输入边界

Clash API 响应限制为 8 MiB，超限、非法 JSON 或尾随额外数据返回错误，响应体仍会关闭。首页为了按代理组做流量采样，会读取活跃连接的最小稳定字段（id/upload/download/chains），但不会物化 metadata、rule 等大块诊断信息；完整连接详情仍只由 DetailedConnections 按需读取。采样热路径复用连接基线 map，避免每秒轮询产生与连接数成正比的临时 map 分配。超过上限的合法大响应也会报错，这是明确的资源保护边界，而不是把失败伪装成空结果。

### TUI 错误退出跳过清理

旧入口在终端错误路径直接 os.Exit，跳过 app.Close。现在交互路径先 return，经 defer 取消并等待自动更新、停止内核、关闭数据库和释放实例锁，最后才由 main 设置退出码。故障注入测试检查内核已停止、数据库已关闭、实例锁可以重新取得。

## 执行方式

```sh
go test -race -count=3 -timeout=5m -run Stability ./cmd/karing ./internal/core ./internal/tui ./internal/clashapi
go test -race -count=3 -timeout=15m ./...
```

新增 Stability workflow 自动执行这两组命令并保留日志与被测源码。现有 CI 继续执行 Linux/macOS 单元与竞态检查、静态检查、性能基准、发布包构建以及带实际 sing-box 二进制的内核/DNS/独立测速集成测试。普通 go test 中依赖 SINGBOX_BIN 的测试可能跳过，不能据此宣称真实内核集成已通过；应核对 CI 的发布包验证步骤。

## 验证边界

这些测试是可重复的加速回归和故障注入，不等于在用户网络、订阅规模和终端环境中连续运行 24/72 小时。没有用户现场的 panic 栈、OOM 记录或内核退出日志，不能断定上述问题就是所有长期退出的唯一原因。若仍然退出，应区分 karing 本身退出、sing-box 退出、终端断开与操作系统终止，保存退出时间、版本、两个进程的 PID/RSS、程序日志和内核日志；分享前移除订阅凭据。
